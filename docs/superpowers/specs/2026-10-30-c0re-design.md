# C0RE — Design Spec

**Date:** 2026-10-30
**Status:** Approved 2026-10-30

## 1. Purpose

C0RE turns the user's home PC into a private, free AI service. Any project — Lenz first,
others later — reaches the PC's local AI (Ollama) through C0RE with its own key, from
anywhere. C0RE decides, per key, whether the project may use the private network only or
also the public internet, which models it may use, and how much.

### Goals

1. **Safe by default.** Ollama is never reachable from outside the PC. Every request needs a
   valid key. The public address is off until the user turns it on.
2. **Per-project control.** One key per project; each key has a reach (private, public, off),
   allowed models and limits; any key can be switched off instantly.
3. **Drop-in for projects.** A project talks to C0RE exactly as it would talk to Ollama (or an
   OpenAI-style API), plus a key.
4. **Light.** One Windows program with low memory use; no runtime to install.
5. **Visible.** A dashboard and a CLI show engine health, keys and usage.

### Environment

- **Host:** Windows 11 PC, RTX 4070 Super (12 GB VRAM), 32 GB RAM, Tailscale machine name
  `kihurn-desktop` (100.94.2.98).
- **Engine:** Ollama 0.40.13 on `127.0.0.1:11434`, `OLLAMA_CONTEXT_LENGTH=8192`,
  `OLLAMA_KEEP_ALIVE=-1`, flash attention on, KV cache `q8_0`. Models include
  `qwen3-vl:8b-instruct` (6.1 GB, 100% GPU at 8K context).
- **Clients:** the user's devices on Tailscale (MacBook Neo, phone), and later hosted
  projects or other people's apps over the public address.

### Success criteria

- A request with a valid private key from the Mac (over Tailscale) streams an answer with
  < 50 ms added by C0RE.
- A request without a key, with a wrong key, with a key that is off, with a private-only key
  on the public address, or for a model the key may not use is rejected with a clear error,
  and Ollama never sees it.
- A public client cannot force a context size that pushes the model off the GPU.
- C0RE uses < 50 MB of RAM idle.
- The dashboard and admin functions cannot be reached from the public address at all.

## 2. Architecture

```
            Internet ──► Tailscale Funnel (https://kihurn-desktop.<tailnet>.ts.net:8443)
                                │
                                ▼
                     127.0.0.1:7071  PUBLIC entrance ─────┐
                                                          │
 Tailscale devices ──► 100.94.2.98:7070 PRIVATE entrance ─┼──► c0re.exe ──► Ollama 127.0.0.1:11434
 The PC itself     ──► 127.0.0.1:7070  PRIVATE entrance ──┘      │
                                                                 ├── /admin  dashboard (private only)
                                                                 └── c0re.db (SQLite)
```

- **One Rust binary**, `c0re.exe`: gateway, dashboard (built-in static files) and CLI.
- **Two entrances, decided by listening socket, never by request content.**
  - *Private*: listens on the PC's Tailscale address and on `127.0.0.1`, port 7070.
  - *Public*: listens only on `127.0.0.1:7071`. The only way to reach it from outside is
    Tailscale Funnel, which forwards public HTTPS traffic to it. A request therefore cannot
    claim the wrong entrance.
- **Ollama stays on `127.0.0.1:11434`**; C0RE is its only door.
- **Funnel** is turned on and off by C0RE (`tailscale funnel --bg --https=8443
  http://127.0.0.1:7071` / `… off`) from the dashboard or CLI. Default: off.

## 3. Keys and policy

### 3.1 Key model

| Field | Meaning |
|---|---|
| `id` | Short public id, e.g. `k_7f3a` (shown in logs and the dashboard) |
| `project` | Human name, e.g. `lenz`, `my-website` |
| `secret` | `c0re_` + 32 random bytes (base62). Shown once at creation; stored only as an Argon2id hash plus a lookup prefix |
| `reach` | `private` · `public` (private + public) · `off` |
| `models` | Allowed model names; empty = all installed models |
| `rate_per_min` | Max requests per minute (token bucket) |
| `daily_cap` | Max requests per calendar day (local time) |
| `max_concurrent` | Requests in flight at once |
| `max_ctx` | Highest `num_ctx` the key may request (default 8192) |
| `max_body_mb` | Max request size (default 20 private, 8 public) |
| `created_at`, `last_used_at`, `note` | Bookkeeping |

Defaults for a new key: private reach, all models, 60/min, 2000/day, 2 concurrent,
8192 ctx. A new **public** key defaults to 20/min, 500/day, 1 concurrent.

### 3.2 Request checks, in order

1. **Entrance + path.** Public entrance: only the API paths in §4. Admin and dashboard paths
   return 404 on the public entrance.
2. **Key present** (`Authorization: Bearer c0re_…`, or `x-api-key`). Missing → 401.
3. **Key valid** (prefix lookup, constant-time hash check). Unknown → 401.
4. **Reach.** `off` → 403 `key_disabled`. `private` key on public entrance → 403
   `key_not_public`.
5. **Body size** ≤ `max_body_mb` → else 413.
6. **Model allowed** (from the JSON body's `model`) → else 403 `model_not_allowed`.
7. **Limits.** Rate, daily cap, concurrency → else 429 with `Retry-After`.
8. **Rewrite unsafe options** before forwarding:
   - clamp `options.num_ctx` to `max_ctx`;
   - drop client `keep_alive` (the server keeps models loaded);
   - forbid nothing else — streaming, images, `think`, tools pass through unchanged.
9. **Forward to Ollama**, streaming the response back as it arrives.
10. **Log** the request (§6).

Failed key checks are rate-limited per source address (e.g. 10 failures/min → temporary
block) so keys cannot be guessed over the public address.

## 4. API exposed to projects

C0RE mirrors Ollama's own API, so existing Ollama clients work by changing the base URL and
adding the key.

| Path | Notes |
|---|---|
| `POST /api/chat`, `POST /api/generate` | Streamed or not, images allowed |
| `POST /api/embed` | Embeddings |
| `GET /api/tags` | Filtered to the key's allowed models |
| `POST /api/show` | Only for allowed models |
| `GET /api/ps`, `GET /api/version` | Read-only engine status |
| `POST /v1/chat/completions`, `GET /v1/models` | Ollama's OpenAI-compatible API, same checks |
| `GET /health` | No key; returns `{ "ok": true }` only (no details) |

Never exposed to keys: `/api/pull`, `/api/push`, `/api/create`, `/api/copy`, `/api/delete`
and any other management path. Models are managed by the admin (dashboard/CLI) only.

Errors are JSON: `{ "error": { "code": "key_not_public", "message": "This key can only be
used on the private network." } }`.

## 5. Admin: dashboard and CLI

### 5.1 Dashboard

- Served at `/admin` on the **private entrance only**; a web app built with TypeScript and
  embedded in `c0re.exe`.
- **Login** with an admin password (Argon2id hash in the DB), set on first run via CLI.
  Session cookie: HttpOnly, SameSite=Strict, 12 h. State-changing requests also require a
  per-session token header.
- **Pages:**
  - **Overview** — engine online/offline, loaded model(s) and GPU share (`/api/ps`), today's
    requests and blocks, requests-per-hour chart, recent requests.
  - **Keys** — list; create (project, reach, models, limits, note); edit; switch off/on;
    delete. The new secret is shown once with a copy button.
  - **Usage** — per key/project over time: requests, average latency, tokens in/out, blocked
    requests by reason.
  - **Models** — installed models with size and capabilities; which are loaded.
  - **Settings** — public address on/off (with its URL), default limits, change password.
- **Design:** follows the Apple design skill (HIG foundations, desktop conventions: sidebar
  with one level, hover and keyboard focus, light and dark appearance, accessible contrast
  and sizes) with its craft lens — one signature element, no template look. Works on a phone
  browser (sidebar collapses to a top menu).

### 5.2 CLI

Same functions from PowerShell on the PC (works directly on the database, no login):

```
c0re serve                     # run the gateway (foreground)
c0re install / uninstall       # start automatically at logon (Task Scheduler)
c0re admin set-password
c0re keys create --project lenz --reach private [--models a,b] [--rate 60] [--daily 2000]
c0re keys list | off <id> | on <id> | delete <id> | edit <id> …
c0re public on | off | status
c0re usage [--key <id>] [--days 7]
c0re status                    # engine, entrances, funnel, version
```

## 6. Usage log

One row per request: time, key id, project, entrance, path, model, HTTP status, block
reason (if any), latency, time to first byte, prompt tokens and output tokens (read from
Ollama's final message). **No prompts, images or answers are stored.** Rows older than
90 days are deleted automatically, and the database is kept under **100 MB** (oldest rows
deleted first). Expected size in normal use: a few MB.

## 7. Running on Windows

- `c0re install` registers a Task Scheduler task that starts `c0re serve` hidden at user
  logon (same session as the Ollama tray app), restarting on failure.
- Config file `%LOCALAPPDATA%\C0RE\c0re.toml` (ports, Ollama URL, Tailscale address,
  defaults); database `%LOCALAPPDATA%\C0RE\c0re.db`; log file alongside.
- On start, C0RE detects the Tailscale address (`tailscale ip -4`); if Tailscale is down it
  serves only `127.0.0.1` and retries every 30 s.
- Funnel prerequisites (one-time, in the Tailscale admin console): MagicDNS and HTTPS
  certificates enabled, and the Funnel permission granted to `kihurn-desktop`. `c0re public on`
  checks these and explains any missing step. Funnel only allows ports 443, 8443 and 10000;
  C0RE uses 8443.
- Windows Firewall: `c0re install` adds an inbound rule for TCP 7070 from `100.64.0.0/10`
  only. Port 7071 needs no rule (localhost).

## 8. Error handling

| Situation | Behaviour |
|---|---|
| Ollama not running | API → 503 `engine_offline`; dashboard shows "Engine offline — open Ollama on the PC" |
| Model not installed | 404 `model_missing` with the model name |
| Client disconnects mid-stream | Cancel the upstream request so the GPU stops working on it |
| Ollama drops mid-stream | Stream ends with an error event; logged as `upstream_dropped` |
| Tailscale down | Private entrance falls back to `127.0.0.1` only; dashboard shows it; Funnel status "unavailable" |
| `tailscale` CLI missing | Public on/off disabled with an explanation |
| DB locked/corrupt | Refuse to start with a clear message (never run without key checks) |
| Port in use | Refuse to start, name the port and the process if known |

## 9. Security notes

- Fail closed: any error in key or policy checking rejects the request.
- Secrets never logged; only key ids.
- Admin surface (dashboard, admin API, model management) never bound to the public entrance.
- Dashboard: strict CSP, no third-party scripts or fonts, all assets embedded.
- Dependencies kept minimal and pinned (`Cargo.lock` committed).

## 10. Out of scope (v1)

- Multiple GPUs / machines (NVIDIA PAIR or similar) — the Ollama URL is configurable so this
  can be added later.
- Users and roles beyond one admin.
- Billing, payments, quotas by token count (requests only in v1; tokens are logged).
- Storing conversations.
- Cloud storage (e.g. Supabase) — all data stays local in v1. A later optional sync could copy
  usage stats or share keys between machines; the request path would still check keys locally.
- Updating Lenz to use C0RE — a separate small change after C0RE ships.
- macOS/Linux service installers (the binary is cross-platform; only installation is Windows).

## 11. Technology

- **Gateway/CLI:** Rust (stable), `axum` + `tokio` (HTTP), `reqwest` (upstream streaming),
  `rusqlite` (bundled SQLite), `argon2`, `clap`, `rust-embed` (dashboard assets), `serde`,
  `tracing`.
- **Dashboard:** TypeScript + Vite + Svelte (small compiled bundle), no CSS framework.
- **Delivery:** cross-compiled `c0re.exe` (x86_64 Windows) plus source, sent as a zip; GitHub
  later at the user's choice.

## 12. Testing

- **Rust unit tests:** key parsing/hashing, policy checks (every rule in §3.2), option
  rewriting, limits, entrance handling.
- **Integration tests:** C0RE in front of a mock Ollama (streaming, drops, slow responses,
  oversize bodies, every rejection path, management paths blocked, both entrances).
- **Dashboard:** type checks, unit tests for formatting/state, screenshot review in light and
  dark, reviewed with the Apple design skill.
- **On the PC (manual checklist):** install, logon start, firewall rule, Funnel on/off, a real
  request from the Mac over Tailscale and from a non-Tailscale device over the public URL,
  RAM use.
